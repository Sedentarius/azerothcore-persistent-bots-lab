# Incidents

Use `INC-*` records for failures with lasting engineering value, such as data corruption, unexplained character-state changes, repeated crashes, or major navigation regressions.

An incident should record:

- detection;
- impact;
- timeline;
- evidence;
- root cause when known;
- fix;
- regression test;
- remaining uncertainty.

Do not rewrite an incident to make the project history look cleaner after a fix.
